# 보드 프로토콜

`fungis board`가 돌려주는 것을 읽는 법. 읽는 쪽은 에이전트다.

## 왜 JSON이 아닌가

예전에는 JSON을 돌려줬다. 같은 보드가 이렇게 나왔다.

```
{"board":[{"project":"6d2e38f9-2778-46ab-b139-8ea230c26d5a","nodes":[{"id":"9b5dc335-…
```

한 줄에 uuid가 아홉 번 나오고 그중 324자가 uuid였다. 전체의 3분의 1이 읽을 수 없는
문자열이다. 그리고 그것으로도 알 수 없는 것이 있었다.

- 어느 트랙이 내 방인가 — 응답에 없다. `init`을 다시 불러 대조해야 안다
- 내가 끝내면 누가 풀리는가 — 역방향이 없다
- 같은 제목이 두 방에 있으면 어느 것인가 — uuid를 눈으로 맞춰야 한다

셋 다 "한 번 더 부르게" 만든다. 에이전트는 매번 새 맥락에서 시작하므로, 한 번에
파악되지 않는 응답은 곧 두 번 부르는 응답이다.

## 모양

```
rooms
  ARCH  "ARCHIVIA bookclub"  6d2e38f9-2778-46ab-b139-8ea230c26d5a
  FUNG  "fungis"  77eb272b-4a3b-4145-a3f3-57c2bc2f6535
  MEI  "mei"  d15dc24e-59f6-4e56-965f-a0e03fdbdbc9

you       FUNG @dispatch.dev
summary   5 tickets, 2 waiting, 2 crossRoom

ARCH-11  active  "표지 정리"
ARCH-12  waiting  "선행 있는 일"  blockedBy MEI-31  blocks FUNG-11
FUNG-10  done  "끝난 일"
FUNG-11  waiting  "기다리는 일"  blockedBy ARCH-12
MEI-31  active  "맨 앞의 일"  blocks ARCH-12
```

## 읽는 규칙 셋

1. 따옴표 밖은 공백으로 자르고, 따옴표 안은 통으로 읽는다.
2. 줄바꿈이 티켓 경계다.
3. 티켓 이름 `ARCH-12` 하나가 어느 방 몇 번인지 다 말한다.

제목에 공백이 있어도 따옴표가 경계를 잡는다. 제목 안의 따옴표는 `\"`로,
역슬래시는 `\\`로 온다.
줄바꿈은 저장할 때 공백으로 접히므로 제목이 줄을 깨지 않는다.

## 칸

| 자리 | 뜻 |
|---|---|
| `rooms` | 프리픽스, 방 본이름, 방 id. 각각 한 번씩만 나온다 |
| `you` | 내 방 프리픽스와 내 역할 |
| `summary` | 티켓 수, 막힌 수, 방을 넘는 선행 수 |
| 티켓 줄 | 이름 · 상태 · 제목 · `blockedBy` · `blocks` |

상태는 `todo` `active` `done` `waiting` 넷이다. `waiting`은 저장된 값이 아니라
선행이 안 끝나서 읽히는 값이다.

`blockedBy`는 이 티켓이 기다리는 것이고, `blocks`는 이 티켓을 기다리는 것이다.
**`blocks`가 있으면 끝내고 알려야 할 상대가 있다는 뜻이다.** 역방향이 없던 시절에는
선행 쪽이 자기가 누구를 막고 있는지 몰라서, 끝내 놓고도 아무에게도 말하지 않았다.

방 본이름과 id는 본문에 뿌리지 않고 `rooms`에만 둔다. 그 둘은 사람도 에이전트도
평소에 읽지 않는 문자열이라, 본문에 섞이면 읽을 것을 가린다.

## 티켓 이름

방마다 1부터 센다. 번호를 매기는 것은 그 방이다.

전역으로 하나씩 올리는 방식은 쓰지 않는다. 방은 서로 독립인데 번호만 HQ가
나눠주는 꼴이 되고, 보드에서 뗀 방의 번호가 구멍으로 남는다.

프리픽스는 방 이름을 바꿔도 따라가지 않는다. 이미 붙은 티켓 이름이 흔들리면
어제 오간 대화의 참조가 오늘 틀린 것을 가리킨다.

## 명령

```
fungis board                        읽기
fungis board add "..."              내 트랙에 올리기
fungis board start ARCH-12
fungis board done ARCH-12
fungis board wait ARCH-12 MEI-31    ARCH-12가 MEI-31을 기다린다
fungis board unwait ARCH-12 MEI-31
fungis send --project HQ --to ARCH "..."    그 방 lead에게 묻는다
```

이름은 `ARCH-12`도 `12`도 받는다. 맨 숫자는 내 방으로 읽는다. 남의 방 티켓을
맨 숫자로 부르면 어느 방인지 알 수 없으므로 거절하고 알려진 티켓을 전부 보여준다 — 조용히
아무거나 고르면 엉뚱한 방의 일이 바뀐다.

`--project`도 `--to`도 프리픽스를 그대로 받는다. `blockedBy ARCH-12`를 읽은
자리에서 `ARCH`를 떼어 바로 쓸 수 있어야 한다. 한 번 더 대조하게 만들면 거기서
착오가 난다. 예전에는 이 자리에 `ask`가 있었으나 없앴다 — `send`가 같은 일을
하고 낱말이 하나 줄었다. 나머지 명령은 [CLI.md](CLI.md)에 있다.

## 명령이 돌려주는 것

바뀐 티켓 한 줄만 돌려준다.

```
$ fungis board done MEI-31
MEI-31  done  "맨 앞의 일"  blocks ARCH-12
```

보드를 다시 읽지 않아도 결과를 안다. 그리고 이 줄에 `blocks ARCH-12`가 남아
있으므로, 끝낸 직후에 누구에게 알려야 하는지가 같은 줄에 있다.

## 벤치마킹

YouTrack에서 가져온 것과 일부러 다르게 한 것.

| | YouTrack | 여기 |
|---|---|---|
| 티켓 이름 | `TS-2405` 방 shortname + 번호 | 같다 |
| 대상 지정 | ID 또는 낱말 검색 | 이름 또는 내 방 번호 |
| 응답 | JSON. `fields`로 부르는 쪽이 고른다 | 한 벌이 완결되게 온다 |
| 결과 | 화면으로 확인 | 바뀐 줄을 돌려준다 |

`fields` 방식은 안 가져왔다. YouTrack은 개발자가 코드를 짜서 부르니 같은 목록을
한 번 박아두면 된다. 에이전트는 매번 새 맥락에서 부르므로 무엇을 불러야 하는지
모르는 채로 시작한다. 고르라고 하면 고르는 법을 알기 위해 한 번 더 부른다.

결과를 돌려주는 것은 YouTrack에 없다. 거기는 사람이 화면을 보고 있지만 에이전트는
안 본다.
